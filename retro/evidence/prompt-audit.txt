That covers `QA-CHECKLIST.md`, `ticket-text.js`, `eval.yml`, `verify.js`, `verify.selftest.js`, `log.js`, the screenshot folders and the security-audit validators.

## Findings (highest confidence first)

**F1. High · Group 2 conflict · `rewrite`**
- **Location:** `todo/README.md:46-47`.
- **Evidence:** "`node todo/evals/run.js` runs 49 behaviour checks … by injecting 35 deliberate bugs."
- **Conflicts with:** `CLAUDE.md:47-48`: "State check counts only in `<project>/evals/README.md`; elsewhere link the latest report."
- **Why obsolete:** the counts are correct today (`run.js` has 84 entries, which is 49 plus 35). The rule exists because hand-restated counts drifted before (retro Edit 12).
- **Direction:** CLAUDE.md is the newer rule (`748ed5a`, today). `todo/README.md` should follow it.

**F2. Medium · Group 2 trigger-case enumeration · `rewrite`**
- **Location:** `.claude/skills/factory-loop/SKILL.md:3`.
- **Evidence:** `Use for "run the loop", "fetch the issue", "do/answer/close the ticket", or any mention of Ticket #N.`
- **Why obsolete:** the description rides in every request (the retro measured about 180 tokens) and lists near-synonymous phrases. An intent category generalises better.

**F3. Medium · Group 2 menu of alternatives · `rewrite`**
- **Location:** `SKILL.md:62`.
- **Evidence:** "using the chrome-devtools tools if they are available … If chrome-devtools is not available, use Claude in Chrome or the built-in browser pane, or drive Chrome over the DevTools protocol, and say which you used."
- **Why obsolete:** four tools are offered with no default. The guide's fix is one default plus an escape hatch. Line 63 already gives a headless-Chrome fallback for screenshots.

**F4. Medium · Group 2 history narrative · `rewrite`**
- **Location:** `todo/evals/README.md:70`.
- **Evidence:** "including every defect the independent security reviews of tickets #12 and #13 found."
- **Why obsolete:** it names incidents rather than the current rule, and it freezes at those two tickets.

**F5. Low · flag** · `SKILL.md:77`
- The step calls `get_status` / `bind_pr` "from the ccd_pr tools". No such tools are in this session's tool list.
- The repo doesn't contradict it, since they belong to the harness, so no edit is proposed. It is worth confirming the step still applies to the harness you run.

**F6. Low · flag** · `.claude/hooks/README.md:54`
- It hard-codes "97 payloads that must be blocked and 64 that must be allowed". These are the same kind of hand-restated count as F1, but CLAUDE.md's rule covers eval counts only.
- I did not verify the numbers against `guard.selftest.js`.

**F7. Low · flag** · `.claude/skills/security-audit/SKILL.md:3`
- The description is long and lists use cases. It is vendored from `cloudflare/security-audit-skill` @ `c1c8a8c`. Local edits would diverge from the pin, so leave it.
